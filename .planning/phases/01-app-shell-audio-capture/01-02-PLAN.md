  <name>Task 1: Implement global hotkey registration</name>
  <files>

  <action>
Create `aihelper/HotkeyManager.swift` that registers a system-wide global hotkey:

1. `HotkeyManager` class:
   - Property `onToggle: (() -> Void)?` — callback invoked when hotkey is pressed
   - Default hotkey: Ctrl+Shift+Space (modifiers: .maskControl + .maskShift, keyCode for Space = 49)
   - Use `CGEvent.tapCreate()` with `.cgSessionEventTap` location to create an event tap that intercepts key events system-wide
   - In the event tap callback, check if the event matches the configured hotkey modifiers and keyCode
   - When matched, call `onToggle?()` on the main thread via `DispatchQueue.main.async`
   - The event tap must be added to the current run loop for it to function
   - Method `start()` to create and enable the event tap
   - Method `stop()` to invalidate and remove the event tap

   **Important notes:**
   - CGEvent taps require Accessibility permissions. The app must request these at launch. Use `AXIsProcessTrusted()` to check, and if not trusted, call `AXIsProcessTrustedWithOptions` with `kAXTrustedCheckOptionPrompt: true` to show the system permission dialog.
   - Import `Carbon` for key code constants if needed, or use raw Int values (Space = 49)
   - The event tap callback is a C function pointer — use a static/global function or `Unmanaged` bridge to access the HotkeyManager instance

2. Update `aihelperApp.swift`:
   - Create `HotkeyManager` instance (can be owned by `MenuBarManager` or the App struct)
   - In `.onAppear` or an `init` block, check accessibility permissions and start the hotkey manager
   - Wire `hotkeyManager.onToggle` to `menuBarManager.toggleRecording()`
   - Remove the temporary "Toggle Recording" menu item OR keep it as a secondary trigger (either is fine)

**Alternative approach if CGEvent tap is problematic:** Use `NSEvent.addGlobalMonitorForEvents(matching: .keyDown)` combined with `NSEvent.addLocalMonitorForEvents(matching: .keyDown)`. This also requires Accessibility permissions but is simpler. The downside is `addGlobalMonitorForEvents` cannot consume the event. For this app, that's acceptable since the hotkey (Ctrl+Shift+Space) is unlikely to conflict.

Choose whichever approach works reliably. Document the choice.

<task type="auto">
  <name>Task 2: Implement microphone audio capture to WAV</name>
  <files>
    aihelper/AudioCaptureManager.swift
    aihelper/MenuBarManager.swift
  </files>
  <action>
Create `aihelper/AudioCaptureManager.swift` that captures microphone audio and writes it to a WAV file:

1. `AudioCaptureManager` class:
   - Uses `AVAudioEngine` for microphone capture
   - Property `isCapturing: Bool` (read-only public)
   - Property `lastRecordingURL: URL?` — path to the most recent recording
   - Audio format: 16kHz sample rate, 1 channel (mono), 16-bit integer PCM — this is the format whisper.cpp expects in Phase 2
   - Method `startCapture()`:
     - Creates output file in `FileManager.default.temporaryDirectory` with name like `aihelper_recording_\(Date().timeIntervalSince1970).wav`
     - Sets up `AVAudioEngine` input node with a tap on the input node's bus 0
     - Converts audio to target format (16kHz mono 16-bit) using `AVAudioConverter` if the hardware format differs
     - Writes audio buffers to the output file using `AVAudioFile`
     - Starts the audio engine
   - Method `stopCapture() -> URL?`:
     - Removes the tap from the input node
     - Stops the audio engine
     - Closes the audio file
     - Returns the file URL of the completed recording
   - Handle errors gracefully (log to console, do not crash)

2. Update `aihelper/MenuBarManager.swift`:
   - Add property `private let audioCaptureManager = AudioCaptureManager()`
   - Update `toggleRecording()`:
     - If not recording: call `audioCaptureManager.startCapture()`, set `isRecording = true`
     - If recording: call `audioCaptureManager.stopCapture()`, set `isRecording = false`, log the output file URL to console (`print("Recording saved to: \(url)")`)
   - Request microphone permission before first capture using `AVCaptureDevice.requestAccess(for: .audio)`. If denied, log a warning and do not start capture.

**Important notes:**
- `AVAudioEngine` tap format may not match our target format directly. Always check the input node's native format and convert if needed.
- The audio file must be a valid WAV file that can be read by standard tools (e.g., `afplay`, `ffprobe`).
- Use `AVAudioFile` for writing — it handles WAV header creation automatically.
- Import `AVFoundation` for audio APIs.
  </action>
