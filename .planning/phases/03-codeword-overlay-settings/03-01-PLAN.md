  <action>
Create SettingsManager as an ObservableObject singleton with @AppStorage-backed properties:

```swift
final class SettingsManager: ObservableObject {
    static let shared = SettingsManager()

    @AppStorage("codeword") var codeword: String = "over"
    @AppStorage("autoEnterEnabled") var autoEnterEnabled: Bool = false
    @AppStorage("insertionMethod") var insertionMethod: InsertionMethod = .typing
    @AppStorage("showOverlay") var showOverlay: Bool = true
    // hotkey is display-only for now (Ctrl+Shift+Space hardcoded)
}
```

InsertionMethod should be a String-backed enum (typing, clipboard) conforming to RawRepresentable for @AppStorage compatibility.

Create SettingsView as a SwiftUI Form with sections:

1. **Recording** section:
   - TextField for codeword (label: "Stop codeword", placeholder: "over")
   - Brief helper text explaining the codeword stops recording by voice

2. **Text Insertion** section:
   - Toggle for "Auto-send Enter after insertion" (bound to autoEnterEnabled)
   - Picker for insertion method: "Typing Simulation" (default) vs "Clipboard Paste"
   - Brief explanation: typing simulation preserves clipboard, clipboard paste is more reliable

3. **Overlay** section:
   - Toggle for "Show recording overlay" (bound to showOverlay)

4. **Hotkey** section:
   - Display current hotkey (Ctrl+Shift+Space) as non-editable text
   - Note: "Custom hotkey configuration coming in a future update"

Use `.formStyle(.grouped)` for native macOS settings appearance. Frame the form with a reasonable min size (~400x350).

Do NOT use the SwiftUI Settings scene (it requires WindowGroup which conflicts with menu-bar-only apps). Instead, we will use a Window scene with an id in Task 2.

**aihelperApp.swift:**
Add a "Settings..." menu item to the MenuBarExtra content (between the recording button and Quit). When tapped, open the settings window. Use `@Environment(\.openWindow)` with a Window scene:

```swift
// Add alongside MenuBarExtra:
Window("aihelper Settings", id: "settings") {
    SettingsView()
}
.windowResizability(.contentSize)
.defaultSize(width: 450, height: 400)
```

In the MenuBarExtra content, add a "Settings..." Button that calls `openWindow(id: "settings")`. To get `openWindow` working from MenuBarExtra, store it via `@Environment(\.openWindow) var openWindow` at the App level and pass it down, or use `NSApp.sendAction` to open the window. The simplest approach on macOS 14+: use `SettingsLink()` if using a Settings scene, or add a Button that uses `NSApp.activate(ignoringOtherApps: true)` followed by opening the window.

Actually, the cleanest approach for a menu-bar-only app: Add the Window scene to the App body alongside MenuBarExtra. In the MenuBarExtra button action, use OpenWindowAction. Since @Environment doesn't work directly in MenuBarExtra on macOS 14, use this pattern:

```swift
Button("Settings...") {
    NSApp.activate(ignoringOtherApps: true)
    // Use NSApp.sendAction for opening window
    if let window = NSApp.windows.first(where: { $0.identifier?.rawValue == "settings" }) {
        window.makeKeyAndOrderFront(nil)
    }
}
```

Or simpler: store a static reference. Find the approach that compiles cleanly. The Window scene with id "settings" will create the window on demand.

Add a private method `simulateReturnKey()` that creates and posts Return key CGEvents.
